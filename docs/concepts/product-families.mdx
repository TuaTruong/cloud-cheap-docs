## Family là gì?

**Family** là cách hệ thống phân loại sản phẩm thành các **nhóm có cùng
tính năng và surface action**. Mỗi sản phẩm thuộc đúng một family.

Ví dụ: hai gói proxy khác nhau (khác giá, khác region, khác nhà cung
cấp phía sau) nếu có cùng đặc tính (vd "IPv4 datacenter, IP cố định")
sẽ thuộc cùng family — UI và logic phía bạn xử lý chúng **giống hệt
nhau**.

<Info>
Family là **contract về tính năng**, không liên quan đến backend. Hệ
thống có thể thêm/bớt family, thêm/bớt nhà cung cấp phía sau mà
không thông báo trước — client phải đọc danh sách family active từ
**response runtime**, không hardcode.
</Info>

## Cách dùng family

### 1. Discover family ở runtime

Đừng hardcode danh sách family — gọi catalog endpoint để biết family
nào đang active:

```bash
GET /api/v2/fetch-proxy-products
GET /api/v2/fetch-vps-products
```

Response trả về array các **family group**, mỗi group có `family`
(tên hiển thị) + `family_code` (machine code) + `plans` (danh sách
plan trong family).

```json
{
  "success": true,
  "data": [
    {
      "family": "<Tên hiển thị>",
      "family_code": "<machine_code>",
      "plans": [
        { "id": 10, "name": "...", "price": 50000, "capabilities": { /* ... */ }, /* ... */ }
      ]
    },
    {
      "family": "<Tên family khác>",
      "family_code": "<machine_code_khác>",
      "plans": [/* ... */]
    }
  ]
}
```

### 2. Render UI động theo response

```jsx
function ProductCatalog({ catalog }) {
  return catalog.data.map(group => (
    <Tab key={group.family_code} title={group.family}>
      {group.plans.map(plan => (
        <PlanCard plan={plan} family={group.family_code} />
      ))}
    </Tab>
  ));
}
```

UI **không cần biết** family nào tồn tại trước — render theo data trả về.

### 3. Quyết định hành vi theo `family_code`

Mỗi plan trong group có `family_code` để bạn dispatch logic:

```js
function flowForFamily(familyCode) {
  // Logic theo từng family_code — không hardcode list
  // Family chưa biết: fallback an toàn
}

function pricingNoteFor(familyCode) {
  // Hiển thị note đặc thù theo family_code
  // Không assume family_code cụ thể nào sẽ tồn tại
}
```

### 4. Quyết định bằng `capabilities`, không qua `family_code`

Khi muốn biết action nào áp dụng cho từng record proxy/VPS, đừng switch
trên `family_code` — đọc trực tiếp `capabilities`:

```js
// Tốt
if (proxy.capabilities.change_ip.can) { showChangeIpButton(); }

// Không nên
if (proxy.family_code === 'proxy_ipv4_datacenter') { showChangeIpButton(); }
```

Lý do: `capabilities` đã áp **runtime override** (state thực của record),
còn `family_code` chỉ cho biết loại sản phẩm.

## Khi family tạm thời không có sản phẩm

Đôi khi một family được hệ thống định nghĩa nhưng **không có SKU nào
active** trong catalog (vd: đang chuyển nhà cung cấp, hoặc nhà cung cấp
tạm dừng).

Khi đó:

- `fetch-*-products` **không trả về group cho family** đó.
- UI phía bạn nên **degrade gracefully** — không render tab rỗng, không
  hardcode list family expected.
- Khi backend khôi phục, family group sẽ xuất hiện trở lại — client
  không cần update.

```js
// Code này robust trước mọi thay đổi family list
catalog.data.forEach(group => {
  if (group.plans.length === 0) return; // bỏ qua family rỗng (hiếm)
  renderTab(group.family, group.family_code, group.plans);
});
```

## Cấu trúc flow cơ bản theo loại sản phẩm

Dù family cụ thể có thể đổi, **flow chung** cho mua / quản lý vẫn ổn định:

<CardGroup cols={3}>
  <Card title="Proxy non-bandwidth" icon="globe">
    Mua theo `quantity` × period → trả về danh sách proxy có `expired_at`.
    Hành động trên từng proxy theo `capabilities` runtime.
  </Card>
  <Card title="Proxy Bandwidth" icon="gauge">
    Mua theo `bandwidth_gb` → mở một gói GB → **generate** proxy list
    từ pool theo filter (country, ASN, sticky/rotating).
  </Card>
  <Card title="VPS" icon="server">
    Mua theo `period` + config → trả về VPS record. Power control,
    reinstall, upgrade — đều theo `capabilities` runtime.
  </Card>
</CardGroup>

Phân biệt 3 flow này qua field `type` của plan trong catalog
(`"proxy"` / `"vps"`) và flag `capabilities.bandwidth_package.is_bandwidth`
(cho proxy bandwidth).

## Best practice

<Info>
Client cần **3 nguyên tắc** khi tích hợp:

1. **Discover** family list từ catalog runtime — không hardcode.
2. **Render** UI động theo response — không assume family nào sẽ tồn tại.
3. **Decision** dùng `capabilities` không qua `family_code` cụ thể.
</Info>

<Warning>
**Không parse `name` / `plan` / `external_*`** của sản phẩm để đoán
backend. Hệ thống cố tình ẩn thông tin đó — backend có thể đổi mà không
báo trước.
</Warning>

<Warning>
**Không hardcode danh sách `family_code`** trong client. Lấy danh sách
family đang active từ `fetch-*-products` mỗi lần render, hoặc cache
ngắn (5–15 phút).
</Warning>

<Warning>
Một số `family_code` có thể bị **xóa** trong tương lai khi sản phẩm
ngừng bán. Client phải handle case `family_code` không nhận diện
được (fallback hiển thị plan bằng `name` + `capabilities`).
</Warning>
