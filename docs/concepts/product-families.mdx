## Vì sao có family?

Sản phẩm trong catalog rất nhiều SKU và **có thể được thay đổi backend
bất cứ lúc nào** (thêm/bớt nhà cung cấp, đổi provider, gộp/tách SKU).
Để code phía bạn **không phải sửa khi backend đổi**, mỗi sản phẩm được
gắn vào một **family** — định nghĩa **theo tính năng** chứ không theo
backend.

<Info>
Family là **contract về tính năng và surface action**, không phải về
nguồn cung. Cùng một family có thể được phục vụ bởi nhiều backend khác
nhau, hoặc tạm thời không có backend nào — phụ thuộc danh mục sản phẩm
hiện tại.
</Info>

Mọi response catalog (`/fetch-proxy-products`, `/fetch-vps-products`) và
mọi record proxy/VPS (`/customer/proxy/list`, `/customer/vps/list`) đều có
hai field:

| Field | Kiểu | Ví dụ |
|---|---|---|
| `family` | string | `"Proxy IPv4 Datacenter"` |
| `family_code` | string (snake_case) | `"proxy_ipv4_datacenter"` |

**`family_code` là khoá ổn định** dùng làm switch logic phía code.
`family` là tên hiển thị — có thể điều chỉnh cho marketing.

## Khi family tạm thời không có sản phẩm

Vì family là **contract về tính năng**, đôi khi family được định nghĩa
trong tài liệu nhưng **tạm thời không có SKU nào active** trong catalog
(ví dụ: chúng tôi đang đổi nhà cung cấp cho dòng đó).

Khi đó:

- `GET /fetch-proxy-products` hoặc `GET /fetch-vps-products` **không trả
  về group cho family** đó.
- UI phía bạn nên **degrade gracefully** — ẩn tab, không hiển thị "empty
  state" với family code không có data.
- Khi backend được khôi phục, family group sẽ xuất hiện trở lại — không
  cần thay đổi code phía bạn.

```jsx
// Tốt: render theo data trả về
catalog.data.forEach(group => {
  renderTab(group.family, group.family_code, group.plans);
});

// Tránh: hard-code family_code list
const FAMILIES = ['proxy_ipv4_datacenter', 'proxy_ipv6', /* ... */];
FAMILIES.forEach(fc => { /* không nên */ });
```

## Cách dùng family

### 1. Lọc catalog theo family

```bash
curl 'https://cloud-cheap.com/api/v2/fetch-proxy-products' \
  -H 'Authorization: Bearer <token>'
```

Response group theo `family_code`:

```json
{
  "success": true,
  "data": [
    {
      "family": "Proxy IPv4 Datacenter",
      "family_code": "proxy_ipv4_datacenter",
      "plans": [
        { "id": 10, "name": "...", "price": 50000, /* ... */ }
      ]
    },
    {
      "family": "Proxy Residential Rotating",
      "family_code": "proxy_residential_rotating",
      "plans": [/* ... */]
    }
  ]
}
```

Phía UI render tab theo family, không hardcode mapping family ↔ backend.

### 2. Phân biệt logic theo family_code

```js
function shouldShowChangeIpButton(proxy) {
  return proxy.capabilities.change_ip.can === true;
}

function priceRangeForFamily(familyCode) {
  switch (familyCode) {
    case 'proxy_residential_static':
    case 'proxy_residential_rotating':
      return { min: 80000, max: 150000 };
    case 'proxy_ipv4_datacenter':
      return { min: 40000, max: 60000 };
    case 'proxy_bandwidth':
      return { min: 0, max: null };
    default:
      return null;
  }
}
```

### 3. Quyết định flow tích hợp

Mỗi family có flow mua + quản lý hơi khác:

- **Proxy non-bandwidth**: mua theo `quantity` × period → trả về danh sách
  proxy có `expired_at`.
- **Proxy Bandwidth**: mua theo `bandwidth_gb` → mở gói GB → **generate**
  proxy list từ pool theo nhu cầu.
- **VPS**: mua theo `period` + config → trả về 1 record VPS, sau đó có
  thể `power-control`, `config`, `upgrade`.

Mỗi flow có trang riêng trong tài liệu này.

## Lưu ý quan trọng

<Info>
Family **ổn định trong thời gian dài** và **độc lập với backend**. Code
client nên dùng `switch (family_code)` với `default` xử lý fallback an
toàn (vd "Sản phẩm này chưa hỗ trợ"). Khi chúng tôi thêm family mới,
client cũ vẫn chạy bình thường — chỉ không hiển thị family mới cho đến
khi code update.
</Info>

<Warning>
**Không bao giờ** parse / đoán backend từ `name`, `plan`, hay
`external_*` của sản phẩm. Chỉ dùng `family_code` + `capabilities` để
quyết định logic. Backend có thể thay đổi mà không thông báo trước —
contract chỉ là family + capability.
</Warning>

<Warning>
**Không hardcode danh sách family_code** trong client. Lấy danh sách
family đang active từ response `fetch-*-products` ở runtime, render
động.
</Warning>
